## 1. 明确 Agent 核心目标和典型使用场景

### 1.1 核心目标

在 LiteOffice 内为用户提供**自然语言驱动的文档理解、编辑辅助与格式转换能力**，降低 Office 操作门槛，同时严格遵守"本地优先、断网可跑、用户授权"的约束。

一句话目标：**让用户用"说话"代替"找菜单"，但所有动作都可解释、可撤销、可拒绝。**

### 1.2 典型使用场景

| 场景 | 用户自然语言 | Agent 行为 |
|---|---|---|
| 文档问答 | "这篇文章主要讲了什么？" | 读取当前文档上下文，生成摘要与要点 |
| 结构化抽取 | "把第 2 段的表格抽出来" | 定位表格 → 调用抽取工具 → 预览 / 导出为 xlsx |
| 格式转换 | "转成 md 发给我" | 校验权限 → 调用转换工具 → 返回文件 |
| 编辑辅助 | "在文末加一段会议纪要" | 生成内容 → 展示差异 → 用户确认后插入 |
| 故障定位 | "为什么在 WPS 里表格报错？" | 调用诊断工具，定位列数不一致并给出修复建议 |
| 兼容性答疑 | "docx 和 pdf 有什么区别？" | 基于知识层回答，不触碰用户文件 |

> 关于 PDF：LiteOffice 的 PDF 能力是**只读**（文字提取 + 页面渲染），没有 PDF 写入器。
> 因此"转成 PDF"不在本期范围内（详见 §4.6 格式能力矩阵）。

## 2. 确定 Agent 能力范围，明确可做与不可做

### 2.1 可做（In-Scope）

- 文档内容问答、摘要、要点提取
- 基于规则 / 模板的编辑**建议**与**草稿生成**（需用户确认才落盘）
- 触发既有能力：格式转换（**docx / xlsx / md / txt / html**）、表格 / 列表结构化抽取
- 文档质量诊断（如表格列数不一致、空单元格等已知缺陷定位）
- 面向当前已打开文档的检索与引用

### 2.2 不可做（Out-of-Scope / 边界）

- **不替代人工终审**：生成内容仅供建议，最终责任在用户
- **不越权访问**：只处理用户明确打开 / 选择的文件，不扫描其他目录
- **不联网抓取**：默认离线；除非用户显式开启并授权联网
- **不执行任意代码**：工具为白名单，禁止运行用户脚本或 shell
- **不保证 100% 格式保真**：合并单元格、图片、编号等在 LiteOffice 往返中本就存在保真度局限；
  docx 导出目前还会丢失图片（已知缺陷）
- **不做 PDF / PPTX 写入**：这两种格式只读
- **不处理违法 / 涉密 / 侵权内容**（见 §6）

### 2.3 明确拒绝的指令

- 生成或传播违法、暴力、歧视、虚假信息
- 处理被标记为涉密 / 个人敏感信息（PII）且未脱敏的内容
- 任何绕过权限、访问未授权文件系统的请求
- 要求"无条件自动覆盖原文件"等不可逆破坏性操作（须人类确认）

## 3. 设计 Agent 架构

采用 **Planner–Tool–Memory–Guardrail** 分层架构，整体运行于浏览器端，推理核心可本地（轻量模型）或经用户授权后远程。

```
┌──────────────────────────────────────────────────────────┐
│  交互层 (Interaction)                                     │
│   聊天 UI / 命令解析 / 流式输出 / 引用标注                  │
└──────────────────────────────────────────────────────────┘
            │ 用户输入
            ▼
┌──────────────────────────────────────────────────────────┐
│  规划层 (Planner)  —— ReAct / 任务分解                     │
│   意图识别 → 工具选择 → 参数填充 → 执行 → 观察 → 反思       │
└──────────────────────────────────────────────────────────┘
       │                │                    │
       ▼                ▼                    ▼
┌─────────────┐  ┌──────────────┐   ┌────────────────────┐
│ 能力层 Tool  │  │ 知识层 Memory│   │ 安全层 Guardrail    │
│ 白名单工具   │  │ 文档上下文/  │   │ 输入过滤/权限/合规  │
│ Registry     │  │ 会话/长期记忆│   │ 人工确认门禁        │
└─────────────┘  └──────────────┘   └────────────────────┘
       │                │                    │
       ▼                ▼                    ▼
┌──────────────────────────────────────────────────────────┐
│  执行沙箱 (Sandbox)                                       │
│   仅调用 LiteOffice 既有能力（转换/抽取/诊断），无系统权限  │
└──────────────────────────────────────────────────────────┘
```

### 3.1 关键组件

- **LLM 推理核心（DeepSeek）**：负责自然语言理解与生成。默认经用户授权的 **DeepSeek API** 调用其云端模型；亦可指向本地部署的 DeepSeek 蒸馏 / 量化版本，或同协议兼容的本地 Ollama。该核心为可插拔模块，离线时由规则引擎替代（见 §5.4）。
- **Planner**：将用户请求分解为可执行的工具调用序列，支持多步反思（ReAct）。
- **Tool Registry**：工具以声明式 schema 注册，便于审计与限权。
- **Memory**：短期（当前会话上下文）+ 长期（用户偏好、历史会话摘要）。
- **Guardrail**：在"输入、规划、执行、输出"四个关口做安全与合规校验。

## 4. 设计工具调用方法

### 4.1 工具定义

每个工具用 **JSON Schema / Function Calling** 风格声明：名称、描述、参数、是否破坏性、所需权限、**实现状态**。

示例（伪 schema）：

```json
{
  "name": "extract_table",
  "description": "抽取当前文档中指定位置的表格为结构化数据",
  "parameters": {
    "target": "string（如 '第2段' / '第1个表格'）",
    "format": "'json' | 'xlsx'"
  },
  "destructive": false,
  "requires": "current_document"
}
```

### 4.2 调用流程

1. **意图识别**：Planner 判断是否需要工具。
2. **工具选择**：从 Registry 匹配，拒绝白名单外调用。
3. **参数填充**：结合 Memory 中的文档上下文补全参数。
4. **权限 / 合规校验**：Guardrail 检查 `requires`、破坏性标记。
5. **执行**：在沙箱中调用 LiteOffice 既有能力，严格超时与错误捕获。
6. **观察与反思**：将结果回灌 Planner，决定继续、澄清或回复。
7. **人工确认门禁**：对破坏性 / 不可逆操作（覆盖、删除、导出覆盖原文件）必须等待用户显式确认。

### 4.3 初始工具清单（含实现状态）

| 工具 | 作用 | 破坏性 | 实现状态 |
|---|---|---|---|
| `read_document` | 读取当前文档文本 / 结构 | 否 | **已有**：`lib/docx.ts:parseDocx`、`lib/xlsx.ts:parseXlsx`、`lib/file.ts` |
| `summarize` | 生成摘要 / 要点 | 否 | 需模型；**离线降级**为取标题 + 首句 |
| `extract_table` | 抽取表格为结构化数据（json / xlsx） | 否 | **已有**：`DocxItem(type='table')`、`xlsx.ts:persistedFromSheet` |
| `convert_format` | 转换到 **docx / xlsx / md / txt / html** | 视目标而定 | **已有**：`lib/exporter.ts:exportDocument` |
| `diagnose` | 定位已知缺陷（表格列数不一致等） | 否 | **待实现**：需新写校验逻辑，当前代码中不存在 |
| `answer_question` | 基于当前文档作答（无独立知识库） | 否 | 降级为"基于当前文档内容 + 模型自身知识" |

### 4.4 失败处理

- 工具超时 / 异常 → 返回错误给 Planner，用自然语言说明并给出替代建议，不静默成功。
- 参数不足 → 向用户澄清（见 §5），不臆测。

### 4.5 工具与现有实现的映射

| 工具 | 调用到的现有函数 |
|---|---|
| `read_document` | `lib/docx.ts:parseDocx`、`lib/xlsx.ts:parseXlsx`、`lib/file.ts:parsePptx`、`lib/pdf.ts:extractPdfText` |
| `extract_table` | `DocxItem(type='table')`、`lib/xlsx.ts:persistedFromSheet` / `sheetText` |
| `convert_format` | `lib/exporter.ts:exportDocument`（docx / xlsx / md）、`exportTextCopy`（txt / html）、`lib/docx.ts:buildDocx`、`lib/xlsx.ts:buildWorkbook` |
| `summarize` | `lib/markdown.ts:htmlToPlainText`（离线）或模型（在线） |
| `diagnose` | 待实现，可基于 `DocxItem(type='table')` 的单元格数一致性检查 |

### 4.6 格式能力矩阵（设计依据，避免承诺做不到的事）

| 格式 | 读取 | 写回 | 说明 |
|---|---|---|---|
| docx | ✅ 段落 / 标题 / 表格 / 图片 / 编号 | ✅ | 导出暂丢图片（已知缺陷） |
| xlsx | ✅ 多工作表 / 单元格 | ✅ | 表名与数据保留 |
| md | ✅ 标题 / 列表 / 代码块 / 表格 | ✅ | 文本级 |
| pdf | ✅ 文字层 + 页面渲染 | ❌ | 无写入器 |
| pptx | ⚠️ 仅抽取文字行 | ❌ | 不解析图片 / 版式 / 表格 |
| txt | ✅ 按 UTF-8 / GB18030 解码 | ✅ | — |

## 5. 设计多轮交互状态管理与用户体验

### 5.1 状态构成

- **短期记忆**：当前会话对话历史、当前文档快照 ID、未完成的多步任务栈。
- **长期记忆**：用户偏好（如默认导出格式）、历史会话摘要（可选、仅存本地 IndexedDB）。
- **文档版本**：每次编辑前存快照，支持引用与撤销。

### 5.2 管理策略

- **上下文窗口**：限定短期记忆长度，超出时压缩为摘要，保留关键引用位置。
- **引用可追溯**：回答中标注依据（如"根据第 2 段表格…"），点击可定位原文。
- **澄清机制**：参数歧义时主动提问，提供候选而非自行猜测。
- **撤销 / 重试**：所有落盘动作可撤销；生成内容支持"重试 / 换一种说法"。
- **离线优先**：与 LiteOffice 断网特性一致——默认全部本地完成，联网为可选 Enhancement。

### 5.3 用户体验原则

- **流式输出**：生成过程可见，避免长等待。
- **进度与可解释**：多步任务显示步骤与当前进度；说明"我为什么这么做"。
- **透明降级**：无模型可用（未授权联网、DeepSeek 不可达）时，退化为基于规则的提示（如"可用工具栏的『导出文本副本』"），不假装智能。
- **最小惊吓**：任何会改变文件的操作前先预览差异。

### 5.4 离线时到底还能做什么

| 能力 | 离线可用 | 说明 |
|---|---|---|
| 表格抽取 | ✅ | 纯本地解析，无需模型 |
| 标题级摘要 | ✅ | 拼接各级标题 + 每段首句 |
| docx / xlsx / md / txt / html 互转 | ✅ | 纯本地 |
| 润色 / 扩写 / 缩写 / 翻译 | ❌ | 需要模型 |
| 自由问答 | ❌ | 需要模型 |

**UI 要求**：不可用的按钮应置灰并说明原因（"离线模式下不可用"），而不是点了没反应。

## 6. 设计安全与合规

### 6.1 数据最小化（可判定条款）

- 助手**默认关闭**（`features.agentEnabled = false`）。关闭状态下不得产生任何 AI 域名请求。
- 每次调用前必须弹确认框，显示：**"将发送 N 字给〈服务商名称〉"** + 选区前 50 字预览。
- 单次发送内容限定为：**用户选中的文字** + 选区前后各不超过 200 字的语境。
- **不发送**：完整文档、文件名、其他会话中的文档。
- 选区超过 2000 字时拒绝发送，提示"选区过长，建议分段处理"。
- **API Key 只存 sessionStorage**，刷新即失效；不写 localStorage、IndexedDB、日志或错误提示。
- **验收方式**：抓包检查请求 body，不得出现上述禁止项。

### 6.2 输入 / 输出过滤

- **输入侧**：拒绝处理违法、涉密、侵权或明显恶意的请求，给出合规说明而非执行。
- **输出侧**：对生成内容标注"AI 生成，仅供参考"；不编造事实，不确定时声明。
- **PII 脱敏**：在涉及个人敏感信息时提示用户脱敏后再处理。
- 说明：纯前端的关键词过滤只能降低误用，**不构成安全边界**，这一点在文档中如实标注。

### 6.3 权限与沙箱

- Agent **仅能操作用户明确打开的文件**，文件系统访问受浏览器沙箱限制。
- 工具白名单之外的任何调用（如执行脚本、访问其他目录）一律拒绝。
- 破坏性操作强制"人工确认门禁"。

### 6.4 审计与可撤销

- 记录关键动作日志（调用了哪个工具、参数、结果），供用户复盘。
- 日志**不记录文档正文**，只记录动作与位置。
- 所有落盘改动可撤销，日志可清除。

### 6.5 透明告知

- 明确告知用户模型的能力边界与局限（尤其格式保真度、不可做清单）。
- 隐私政策以简洁方式在首次启用时呈现。

## 7. 落地分级

| 阶段 | 内容 | 工期 | 依赖 |
|---|---|---|---|
| **H0** | 选区改写：润色 / 扩写 / 缩写 / 翻译 + 候选卡片 + 替换 + 撤销 | 2 天 | 仅前端；可先用 Mock provider |
| **H1** | 工具调用：`read_document` / `extract_table` / `summarize` / `convert_format` | 2 天 | H0 + 一次函数调用循环 |
| **H2** | 多步 ReAct + 长期记忆 + 审计日志 + `diagnose` | 1 周 | H1 + 错误恢复策略 |

**H0 即可演示**，且 Mock provider 让答辩现场无需网络。

## 设计要点小结

| 维度 | 关键决策 |
|---|---|
| 目标（§1） | 自然语言驱动文档理解 / 编辑 / 转换，可解释、可撤销、可拒绝 |
| 边界（§2） | 本地优先、不越权、不联网、不执行任意代码、不做 PDF / PPTX 写入、不保真承诺 |
| 架构（§3） | Planner–Tool–Memory–Guardrail 分层，运行于浏览器端，推理核心 DeepSeek |
| 工具（§4） | 声明式白名单 + Function Calling + 人工确认门禁；清单标注实现状态与函数映射 |
| 交互（§5） | 短期 / 长期记忆分离、引用可追溯、澄清、撤销、离线优先、离线能力清单 |
| 安全（§6） | 可判定的数据最小化条款、输入 / 输出过滤、沙箱限权、审计可撤销、透明告知 |
| 落地（§7） | H0 选区改写 → H1 工具调用 → H2 多步 ReAct |

> 该设计直接复用 LiteOffice 既有能力（转换 / 抽取 / 诊断）作为工具底座。
> AI 助手**无需额外后端**；多人协作则必须有后端，两者是独立的两条线。
