LiteOffice｜AI 助手面板接入 —— 实现任务书

版本 v1.0   日期 2026-10-26
对象：liteoffice-vue 工程（code/frontend）
目标：把侧栏「AI 助手」从死占位改成真正可用的对话面板，并展示 agent 的 ReAct 执行过程。
原则：只加一个面板 + 一处接线，其余一律不许动。


【一、现状（问题证据）】

  1. 侧栏「AI 助手」按钮点击无任何反应
     code/frontend/src/components/app/Sidebar.vue:51
       @click="emit('reserved', 'AI 助手')"
     这个事件没有接收方，属于占位，点了等于没点。

  2. 前端从未调用过 agent 接口
     grep -r "/v1/agent" code/frontend/src  → 0 处

  3. 后端其实已经就绪（已实现并自检通过）
     POST {AGENT_BASE}/v1/agent/run
     功能：LangGraph + ReAct 循环（think → act → 循环 → final，最多 5 步）


【二、接口契约（必须严格按这个调用）】

  请求
    POST  {AGENT_BASE}/v1/agent/run
    Content-Type: application/json
    Body: { "html": "<当前文档 HTML>", "query": "用户问题" }

  响应
    {
      "ok": true,
      "answer": "汇总后的回答",
      "steps": [
        { "phase": "think", "detail": "决定调用工具：get_stats" },
        { "phase": "act",   "detail": "get_stats → 正文 45 字，2 段…" },
        { "phase": "final", "detail": "汇总 3 条观察结果" }
      ],
      "observations": [ { "tool": "get_stats", "ok": true, "summary": "…" } ],
      "toolsUsed": ["get_stats", "diagnose_report"],
      "mock": false
    }

  其他可用接口
    GET {AGENT_BASE}/health          健康检查 → { ok: true }
    GET {AGENT_BASE}/v1/llm/info     模型状态 → { hasCredentials: false } 时表示 mock

  AGENT_BASE 默认 http://127.0.0.1:8101，必须可通过 VITE_AGENT_BASE 覆盖。


【三、必须实现的行为（逐条可验收）】

  1. 侧栏「AI 助手」点击后打开面板
     · 角标从「预留」改为「可用」
     · 同一状态要被右下角浮动按钮共享（两个入口打开同一个面板）

  2. 默认关闭，未打开前零请求
     · 面板收起时不得发任何网络请求
     · 这也是隐私要求：用户没点，就不该连后端

  3. 空状态给示例问题（识别优于回忆）
     至少 3 条，例如：
       「这份文档有多少字」
       「检查一下表格和标题有没有问题」
       「帮我看看有哪些重复段落」
     点击即发送。

  4. 未打开文档时
     · 输入框禁用或发送后提示「请先打开一份文档」
     · 不得发出请求（因为 html 为空，发了也没意义）

  5. 发送后展示执行过程（这是本任务的重点）
     · 答案正文
     · 折叠/列表展示 steps：每行是 [想]/[做]/[答] + detail
     · 显示用到的工具名
     · 显示 mock 标记（后端返回 mock=true 时显示「离线模拟」徽章）

  6. 等待与取消
     · 发送后显示「正在执行… 已等待 N 秒」，每秒递增
     · 提供「取消」，取消后恢复可输入，不改变任何文档内容
     · 单次请求超过 30 秒仍未返回 → 提示「后端响应超时」并给重试

  7. 错误可读
     分四类给不同文案 + 重试：
       后端未启动（fetch 失败）  → 「AI 服务未启动（端口 8101），请先启动后端」
       HTTP 4xx              → 显示后端返回的 detail
       HTTP 5xx              → 「服务内部错误，可重试」
       超时                  → 同上第 6 条

  8. 不改动文档内容
     · 面板只读调用 agent，不做任何写入
     · 不修改正文、不压撤销栈

【五、硬性约束】

  · 不引入任何新依赖（不要组件库、不要 markdown 渲染库）
  · 不改现有页面结构：Home.vue / Editor.vue / TopBar.vue 的布局不得变动
  · 不把面板做成新路由（用浮层，避免影响既有导航）
  · 面板代码必须懒加载：只在首次打开时加载（动态 import），
    保证关掉时首屏体积不变
  · 离线（navigator.onLine === false）时：按钮可点，但面板内提示
    「当前离线，AI 需联网；本地功能不受影响」
  · 不发送整篇文档给模型：本任务的 agent 是本地工具编排，
    请求 html 只用于本地解析，不调用外部模型（mock 模式即是本地）

【六、验收清单（交付时必须逐条给出证据）】

  1. 点侧栏「AI 助手」→ 面板出现（贴截图）
  2. 面板收起状态下 DevTools Network 清空后等待 10 秒 → 无任何请求
  3. 未打开文档时点示例问题 → 提示「请先打开一份文档」，无请求
  4. 打开一份 docx 后问「这份文档有多少字」→ 5 秒内出答案
     且显示 ≥3 步执行过程（贴截图）
  5. 后端未启动时点击发送 → 显示「AI 服务未启动（端口 8101）」而非白屏
  6. 发送中显示「已等待 N 秒」，点取消后恢复可输入
  7. 面板打开前后，首页主包体积不变（对比 dist 中 index-*.js 大小）
  8. npm run build 通过，vue-tsc 零错误

【七、交付物】

  · 改动文件清单（应只有 3–4 个：Sidebar.vue、App.vue 或新面板组件、一个新 api 封装）
  · 新增依赖清单（应为 0）
  · 构建日志与 dist 体积变化
  · 上面 8 条验收的截图或终端输出


【八、禁止事项】

  · 不要把 agent 逻辑写进前端（前端只调接口，推理在后端）
  · 不要在面板里做「自动替换正文」这类写操作（属于下一阶段）
  · 不要用假数据冒充结果（mock 时必须显式标注）
  · 不要改主题色值、圆角、间距体系
  · 不要引入 WebSocket（本任务只需 HTTP）
