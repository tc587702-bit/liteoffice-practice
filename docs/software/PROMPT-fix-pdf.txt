【问题 1：PDF 提取完全失效（必须修）】

  证据（四个真实文件，均为 Word 导出的文本型 PDF，不是扫描件）
    chk.pdf          373 KB，含 115 个 /Font、19 个 /ToUnicode  → 提取 0 字符
    margin_test.pdf  11 KB                                    → 提取 0 字符
    re2.pdf          292 KB                                   → 提取 0 字符
    re_tmp.pdf       364 KB                                   → 提取 0 字符
    四个都返回 method=none，提示"可能是扫描件或使用了不可提取的文字编码"

  判断
    lib/pdf.ts 的自研解析器处理不了真实 PDF 的交叉引用流、对象流、CID 字体。
    自研方案在这个体量上不成立，放弃。

  要求
    1. 改用 pdfjs-dist（npm 安装，版本写已发布的稳定版或 latest）
    2. worker 必须本地打包，禁止任何 CDN 或远程地址：
       用 new URL('pdfjs-dist/build/pdf.worker.min.mjs', import.meta.url) 交给 Vite 处理
    3. 先做文本提取（getTextContent），有文字层就按页输出文本
    4. 再渲染页面 canvas（可懒加载，只渲染可见页）
    5. 失败必须区分原因并给人话提示：
         无文字层        → "这是扫描件，暂不支持 OCR"
         加密            → "PDF 已加密，请先解除密码保护"
         文件损坏        → "PDF 结构异常，无法解析"
         其他            → 给出具体错误
    6. 禁止静默返回空字符串

  验收（交付时必须给出实测数字）
    对上述四个文件分别报告：页数 / 提取字符数 / 首行文本 / 耗时(ms)
    chk.pdf 至少提取 1000 字符；不得出现"0 字符且无原因"


【问题 2：xlsx 大文件回退路径不可用（必须修）】

  证据
    大型工作簿.xlsx（6.7 MB，约百万单元格）
    内置回退解析器耗时 27015 ms，且静默截断到 4000 行，只给一句 warning
    界面在这 27 秒内没有任何进度反馈

  要求
    1. SheetJS 主路径保持不动
    2. 回退路径加前置保护：文件 > 2 MB 或估算行数 > 20000 时，
       先提示"文件较大，将只加载前 20000 行"，用户确认后再解析
    3. 解析期间必须有等待态（进度或至少"正在解析 N 秒"），不许界面假死
    4. 超过 5 秒未完成要给出可取消入口
    5. 截断必须显式标注："已截断，仅显示前 N 行（共 M 行）"

  验收
    6.7 MB 文件：要么 5 秒内给出前 20000 行并显式标注已截断，
    要么在 1 秒内直接提示过大并给出替代方案；不允许 27 秒白屏无反馈
