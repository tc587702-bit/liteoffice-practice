## 0. 体例

每条故事三层：

1. **用户故事**——固定三行，只写价值，不写控件与选型：
   ```
   角色：作为〈谁〉
   功能：我想要〈能力〉
   价值：以便〈解决什么问题〉
   ```
2. **验收标准**——Gherkin 场景，`Given / When / Then / And`，一条场景只验一件事。关键词用英文，内容用中文。
3. **反例（不算通过）**——最容易扯皮的是"没触发但也没报错"，命中任一条即判未完成。

状态含义：`已验收`（实测通过）、`已实现待验`（代码有、证据缺）、`未实现`（**答辩中不得声称可用**）。

## 2. 三条不变承诺

新增功能不得改动这三条，它们是 US-11 的判定依据。

| 承诺 | 含义 | 判定方式 |
|---|---|---|
| **① 断网可用** | 打开、预览、编辑、保存全程不依赖网络 | 断网后重跑核心操作，行为一致 |
| **② 单人模式零上传** | 文件内容不离开本机内存 | Network 中无任何第三方域名的请求体 |
| **③ 新功能可关闭且互不干扰** | 协作与 AI 关闭时，行为与体积等同于没有它们 | 关掉开关后重跑 US-01~US-04 |

> 协作是**唯一**会改变 ② 的功能：发起协作后内容写入你自己的服务器。
> 对外口径只能写成："**单人使用全程不上传；发起协作时内容只存到你自己的服务器。**"

## 3. 故事与验收标准

### US-01 打开即读，多文件随手切

**优先级** P0　**状态** 已验收（docx / xlsx / pdf / md 四种格式浏览器实测通过）
**对应需求** FR-FILE-02、FR-PRV-01、FR-PRV-04、FR-MD-01、FR-MD-05

```
角色：作为一名学生
功能：我想要把老师发的文件拖进网页就立刻看到内容，并能在多份文件之间随手切换
价值：以便不装 Office 也能改作业模板、快速对比同学的版本
```

**验收标准**

```gherkin
场景：拖入后立刻渲染
  Given 用户打开 LiteOffice 首页且尚未选择文件
  When  用户把 common.docx 拖入窗口任意位置
  Then  页面应在不刷新、不跳转的情况下展示文档正文
  And   侧栏应显示文件名、大小与格式徽章
  And   应在 1 秒内出内容

场景：四种格式各打开一次
  Given 用户已打开 LiteOffice
  When  依次拖入 docx、xlsx、pdf、md 各一份
  Then  四种格式都应显示为对应排版，而不是纯文本或下载提示
  And   docx 内的图片应以图片形式显示，不是破图或空白
  And   xlsx 应显示为表格并保留表头

场景：快速连续切换以最后一次为准
  Given 侧栏已有 A、B、C、D 四份文档
  When  用户快速连续点击 B、C、D
  Then  最终展示的应是 D 的内容
  And   不应出现 B 或 C 的旧内容覆盖 D

场景：md 里的脚本不执行
  Given 一份 md 内容里写有 <script>alert(1)</script>
  When  用户打开该文件
  Then  页面不应弹出对话框，该段应作为普通文字显示
  And   不应向任何第三方域名发起请求
```

**反例（不算通过）**

- 显示"正在解析…"后一直不动，最终也没出内容。
- docx 能出文字但图片位置是空白或破图。
- 切换时先闪一下旧文档，再显示新文档。

### US-02 断网也能用，且一个字节都不上传

**优先级** P0　**状态** 已实现待验（缺断网录屏与 Network 截图）
**对应需求** FR-FILE-04

```
角色：作为一名处理成绩单的行政人员
功能：我想要断网也照样打开、编辑、保存，并能确认没有任何上传
价值：以便放心处理含个人信息的表格
```

**验收标准**

```gherkin
场景：完全离线跑完核心流程
  Given 用户已成功加载过 LiteOffice 页面
  And   设备网络已断开
  When  用户拖入 common.xlsx、编辑一个单元格、点击保存下载
  Then  打开、编辑、保存三步都应成功
  And   状态栏应显示"内容只在本地内存中，未上传"
  And   不应出现"请检查网络"一类错误

场景：零上传可证
  Given 用户打开 DevTools 的 Network 面板并清空记录
  When  用户打开任意文档并完成预览与保存
  Then  不应出现携带文件内容的 XHR / Fetch / WebSocket 请求
  And   域名列表只应包含本机地址（localhost / 127.0.0.1 / 局域网 IP）

场景：离线状态有可见标识
  Given 浏览器处于离线状态
  When  用户查看顶栏
  Then  应显示"离线可用"标签
  And   网络恢复后该标签应消失
```

**反例（不算通过）**

- 断网后能打开但保存失败。
- 只有页面自身不发请求，却加载了统计脚本。
- 离线时整页提示"请检查网络"。

### US-03 改完就存，文件名不变

**优先级** P0　**状态** 已实现待验
**对应需求** FR-EDT-01、FR-SAV-01、FR-SAV-02

```
角色：作为一名学生
功能：我想要改个错别字就直接保存，存下来还是"报告.docx"
价值：以便直接交回给老师，不用另存再改名
```

**验收标准**

```gherkin
场景：进入编辑并修改
  Given 用户已预览 common.docx
  When  用户点击"编辑"并在正文里修改一个错别字
  Then  编辑区应可输入，修改即时可见
  And   光标应落在文字所在行内，不出现整行偏移

场景：保存沿用原文件名
  Given 用户处于编辑态且已有修改
  And   下载目录中不存在同名文件
  When  用户点击"保存下载"
  Then  应触发一次下载，文件名为 common.docx
  And   重新打开该文件应能看到修改

场景：保存失败内容不丢
  Given 用户正在编辑且有未保存修改
  When  保存过程发生错误
  Then  应提示失败原因与替代操作
  And   编辑内容应保留，不得清空
```

**反例（不算通过）**

- 保存后文件名变成 download 或一串哈希。
- 保存成功但重新打开看不到修改。
- 出错时编辑区被清空。

### US-04 出错说人话，能力可开关

**优先级** P1　**状态** 已验收
**对应需求** FR-FILE-03、FR-ERR-01、FR-CFG-01、FR-CFG-02

```
角色：作为一名要把文档能力嵌进自己网页的开发者
功能：我想要出错有明确提示、能力能用开关关掉
价值：以便低成本集成，且故障时能判断是格式问题还是功能被关
```

**验收标准**

```gherkin
场景：伪装文件被拒绝
  Given 一个 txt 文件被改名为 fake.docx
  When  用户把它拖入页面
  Then  应明确提示"不是有效的 docx"并说明原因
  And   界面框架应保留，不出现白屏

场景：异常不白屏
  Given 用户人为制造一次解析失败
  When  失败发生
  Then  应出现红色横幅说明原因
  And   用户应能切回其他文档继续工作

场景：开关关闭后干净退化
  Given 把 features.agentEnabled 与协作开关都置为 false
  When  用户打开文档并操作
  Then  界面上不应出现 AI 助手与协作入口
  And   Network 中不应出现 AI 域名请求或 WebSocket 连接
  And   其余功能应完全不受影响
```

**反例（不算通过）**

- 把文件改成 .docx 后提示"未知错误，请重试"。
- 出错后整页面空白，只能刷新。
- 关掉开关后仍有 AI 相关请求。

### US-05 一键发起协作并分享链接

**优先级** P2　**状态** 未实现（需后端，验收标准按目标行为写）
**对应需求** FR-COLLAB-01、FR-COLLAB-02

```
角色：作为一名小组长
功能：我想要点一下就把当前文档变成多人协作，并复制链接给组员
价值：以便大家同时改一份报告，不用来回传文件、也不用合并版本
```

**验收标准**

```gherkin
场景：发起协作并明确告知上传
  Given 用户已打开"报告.docx"且处于单人模式
  When  用户点击顶栏"发起协作"
  Then  应弹窗说明"协作会把文档存到你的服务器"，需确认后才上传
  And   确认后应显示"可编辑"与"仅查看"两种链接
  And   顶栏应显示"协作中"与在线人数"1 人"
  And   Network 中应出现一次上传请求，且请求体只含该文档

场景：复制链接并加入
  Given 协作已开启
  When  用户点击"复制链接"并把链接发到群里，组员打开它
  Then  组员应直接进入房间，无需注册或登录
  And   双方顶栏都应显示"2 人"

场景：重置链接使旧链接失效
  Given 已把"仅查看"链接发到群里
  When  用户点击"重置链接"
  Then  旧链接再次打开应提示"链接已失效，请向发起者索取新链接"
  And   已在房间内的成员不应被踢出

场景：结束协作
  Given 协作正在进行
  When  用户点击"结束协作"
  Then  其他成员应收到"发起者已结束协作"提示
  And   文档内容应已持久化，原链接仍可查看
```

**反例（不算通过）**

- 点"发起协作"后直接上传，没有任何提示。
- 链接需要注册账号才能打开。
- 重置链接后房间内成员全部掉线。

### US-06 多人同时改同一份，不互相覆盖

**优先级** P2　**状态** 未实现
**对应需求** FR-COLLAB-03、FR-COLLAB-04

```
角色：作为一名组员
功能：我想要看到别人改了哪里、光标停在哪，并确保我写的内容不会被覆盖
价值：以便不重复劳动，也不会互相冲掉对方的修改
```

**验收标准**

```gherkin
场景：对方输入实时可见
  Given A 已发起协作，B 用"可编辑"链接加入
  When  B 在第二段输入 20 个字
  Then  A 的编辑区应在 500 毫秒内出现相同文字（同一局域网）
  And   A 不需要手动刷新

场景：同段同时输入不互相覆盖
  Given A 与 B 同时在第一段末尾各输入不同文字
  When  两人停止输入
  Then  两人新增的文字都应保留
  And   不应出现"后输入者整段覆盖前者"
  And   段落不应被复制成两份

场景：看到对方身份与位置
  Given A 与 B 都在房间内
  When  B 把光标放到第三段
  Then  A 应看到带 B 昵称与颜色的光标标记
  And   顶栏在线人数应为"2 人"

场景：大幅改写也不丢内容
  Given 同一段落被两人同时大幅改写
  When  合并完成
  Then  两份文字都应保留在文档中
  And   不应出现内容被截断到半句的情况

场景：成员离开后标记消失
  Given A 能看到 B 的光标
  When  B 关闭页面
  Then  A 侧的光标标记应在 5 秒内消失
  And   在线人数回落为"1 人"
```

**反例（不算通过）**

- 双方都能输入，但各自看到的内容不同（最后谁保存谁赢）。
- 一个人打字时另一个人的光标乱跳。
- 合并后出现重复段落。

### US-07 只读链接与掉线恢复

**优先级** P2　**状态** 未实现
**对应需求** FR-COLLAB-05、FR-COLLAB-06

```
角色：作为一名组员
功能：我想要能把只读链接发给老师看，并且网络抖一下也不丢内容
价值：以便既能给别人看又不被误改，写得放心
```

**验收标准**

```gherkin
场景：只读链接不能编辑
  Given 用户用"仅查看"链接打开文档
  When  用户点击正文并尝试输入
  Then  输入不应生效，正文保持不变
  And   应提示"当前为只读链接，如需编辑请向发起者索取编辑链接"

场景：断网后恢复不丢内容
  Given A 与 B 正在协作
  And   B 的网络断开 10 秒，期间 A 输入了 30 个字
  When  B 的网络恢复
  Then  B 应在 3 秒内补齐这段时间的内容
  And   不应出现重复段落或段落缺失

场景：发起者离线仍可打开
  Given 房间内容已持久化在服务端
  When  发起者关闭浏览器后，组员再次打开原链接
  Then  文档内容应完整可读，不依赖发起者在线

场景：服务端重启后链接仍可用
  Given 协作房间已存在且有内容
  When  服务端重启且用户重新打开原链接
  Then  文档内容应完整恢复
  And   在线人数从头开始计数
```

**反例（不算通过）**

- 只读链接能通过开发者工具改成可编辑。
- 断线期间输入的内容在恢复后丢失，或产生重复段落。
- 发起者一关浏览器，链接就打不开。

### US-08 让 AI 润色我选中的那一段

**优先级** P1　**状态** 未实现
**对应需求** FR-AGENT-02、FR-AGENT-05、FR-AGENT-06

```
角色：作为一名要交实验报告的学生
功能：我想要选中一段让 AI 润色，先看效果再决定是否替换
价值：以便不用整篇重写，也不怕被 AI 改坏交上去
```

**验收标准**

```gherkin
场景：选区出现操作菜单
  Given 用户已打开 docx 并处于编辑态
  When  用户选中一段 20 字以上的正文
  Then  选区附近应出现菜单（润色／扩写／缩写／翻译／摘要）
  And   未选中文字时菜单不应出现

场景：先预览，不自动覆盖正文
  Given 用户选中一段并点击"润色"
  When  结果返回
  Then  应以候选卡片显示，不直接写入正文
  And   卡片应提供"替换""插入下方""复制""丢弃"
  And   点"丢弃"后正文应与替换前逐字一致

场景：替换可撤销
  Given 用户点击"替换"且候选文字已写入正文
  When  用户按 Ctrl+Z
  Then  正文应完整还原为替换前的内容（含原有分段与加粗）

场景：表格内不提供改写
  Given 选中的区域位于表格单元格内
  When  用户尝试触发菜单
  Then  菜单应置灰并提示"表格内暂不支持 AI 改写"
  And   不应发起任何网络请求
```

**反例（不算通过）**

- AI 返回后直接覆盖正文，用户来不及看一眼。
- 按 Ctrl+Z 只撤掉半句，或把格式一起撤没了。
- 表格里也能改写，导致表格结构散架。

### US-09 和 AI 边聊边写

**优先级** P1　**状态** 未实现
**对应需求** FR-AGENT-03、FR-AGENT-07

```
角色：作为一名不知道从哪下笔的学生
功能：我想要在侧栏问 AI"这份文档帮我列个提纲"，让它结合当前文档回答
价值：以便不用离开页面去别的工具里绕一圈
```

**验收标准**

```gherkin
场景：对话能感知当前文档
  Given 用户已打开一份 docx 并打开 AI 面板
  When  用户输入"把这份文档的要点列成三条"
  Then  回答应基于当前文档内容，而不是通用套话
  And   回答应流式显示，不是长时间空白后一次性出现

场景：把回答用进文档
  Given AI 已给出可插入的内容
  When  用户点击"插入到光标处"
  Then  内容应写入光标位置
  And   应可用 Ctrl+Z 撤销

场景：生成中可中断
  Given 正在流式返回文字
  When  用户点击"停止"
  Then  应在 1 秒内停止接收
  And   正文与撤销栈都不应改变
```

**反例（不算通过）**

- 问的是"这份文档"，回答却是通用模板。
- 点"插入"后内容出现在文档末尾而不是光标处。
- 点"停止"后仍继续往正文里写字。

### US-10 只发选区，服务商看不到其余内容

**优先级** P1　**状态** 未实现
**对应需求** FR-AGENT-01、FR-AGENT-03、FR-AGENT-04、FR-AGENT-09

```
角色：作为一名要处理含个人信息文档的用户
功能：我想要在发送前看到"要发多少字、发给谁"，并确认只发我选中的部分
价值：以便敢用 AI，也不违背我选这个工具的原因
```

**验收标准**

```gherkin
场景：默认关闭时零请求
  Given features.agentEnabled 为 false（默认值）
  When  用户打开文档并正常编辑、保存
  Then  页面上不应出现 AI 助手入口
  And   Network 中不应出现任何 AI 服务商域名请求

场景：发送前显示字数与预览
  Given 助手已开启
  When  用户选中 137 字并点击"润色"
  Then  应弹出确认框，显示"将发送 137 字给 <服务商>"与前 50 字预览
  And   点"取消"后不应发出任何请求，正文不变

场景：请求体只含选区
  Given 用户已在确认框中点击"确认"
  When  抓包查看该请求的 body
  Then  请求体应只包含选区文字（可附带选区前后各不超过 200 字的语境）
  And   不应包含文件名、文档其余段落、其他会话文档的任何内容

场景：超长选区被拦截
  Given 用户选中超过 2000 字的正文
  When  用户点击"润色"
  Then  应提示"选区过长，建议分段处理"
  And   不应发送请求，正文不变

场景：API Key 不落盘
  Given 用户已填入 Key 并成功调用一次
  When  用户关闭页面后重新打开
  Then  应要求重新输入 Key
  And   localStorage 与 IndexedDB 中不应存在明文 Key
```

**反例（不算通过）**

- 确认框只写"确定要使用 AI 吗"，不显示字数与服务商。
- 请求 body 里带着整篇文档或文件名。
- Key 被写进 localStorage 或出现在报错信息里。

### US-11 新功能不许拖累原有能力

**优先级** P0　**状态** 未实现（机制需随两个功能一起落地）
**对应需求** §2 三条不变承诺、FR-CFG-01、FR-CFG-02、FR-FILE-04

```
角色：作为一名已经把 LiteOffice 当日常工具的用户
功能：我想要协作和 AI 加进来之后，打开速度、离线可用性、零上传都不变差
价值：以便新功能是加分项，而不是让原来的好处打折扣
```

**验收标准**

```gherkin
场景：关掉新功能等于没有它们
  Given agentEnabled 与协作开关都为 false
  When  用户重跑 US-01~US-04 的全部场景
  Then  行为应与加入新功能之前完全一致
  And   Network 中不应出现 AI 域名请求或 WebSocket 连接

场景：首屏不变胖
  Given 生产构建产物
  When  统计 dist 体积
  Then  首屏主包应 ≤ 350 KB（不含按需加载的 pdf / xlsx 分块）
  And   协作与 AI 的代码应是按需加载，不出现在首屏

场景：离线时协作优雅降级
  Given 网络已断开
  When  用户点击"发起协作"
  Then  应提示"协作需要网络，当前为离线模式，本地功能不受影响"
  And   不应出现白屏或无限转圈
  And   打开、编辑、保存、md 预览应照常可用

场景：AI 不阻塞核心链路
  Given 一个 AI 请求正在进行（或已卡住）
  When  用户同时进行打开、编辑、保存
  Then  三步都应正常完成，不被阻塞
  And   AI 出错不应影响到保存结果
```

**反例（不算通过）**

- 加入协作后首屏必须等 WebSocket 连上才能用。
- AI 面板打开时保存按钮变慢或失灵。
- 离线时整页功能降级，只留一句"协作不可用"。
