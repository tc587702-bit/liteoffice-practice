## 0. 体例

每条故事三层：

1. **用户故事**——固定三行，只写价值，不写控件与选型：
   ```
   角色：作为〈谁〉
   功能：我想要〈能力〉
   价值：以便〈解决什么问题〉
   ```
2. **验收标准**——Gherkin 场景，`Given / When / Then / And`，一条场景只验一件事。
   关键词用英文（工具链可直接解析），内容用中文。
3. **反例（不算通过）**——Gherkin 只描述正例，验收时最容易扯皮的就是"没触发但也没报错"。
   命中任一条反例，这条故事即判未完成。

**粒度**：单人 0.5–2 天、能当场演示；超过 2 天必须拆
（对齐 [github_projects_setup.md](../mgmt/github_projects_setup.md) 的 `Estimate ≤ 2 天`）。

## 2. 故事与验收标准

### US-01 多格式打开与秒级预览

**用户故事**

```
角色：作为一名要在课上改老师发来模板的学生
功能：我想要把 docx / xlsx / pptx / pdf 直接拖进网页就看到内容
价值：以便不用为了看一眼排版去装一整套 Office
```

**对应需求**：FR-FILE-02、FR-PRV-01、FR-PRV-03

**验收标准**

场景：拖入 docx 并即时预览
```
Given 用户打开工作台且尚未打开任何文件
When  用户把一份 1.2 MB 的 docx 拖到窗口任意位置（顶栏 / 侧栏 / 编辑区）
Then  界面应出现虚线遮罩提示"松手即可打开"
And   松手后 1 秒内正文应可见
And   侧栏应新增一条记录并高亮为当前文件
```

场景：快速切换文件不错配
```
Given 用户已依次打开 docx、xlsx、pptx 三个文件
When  用户快速连续点击侧栏中的三条记录
Then  编辑区最终显示的应是最后点击的那一个文件
And   不应残留上一个文件的内容
```

**不算通过**
- 拖放到顶栏或侧栏无效（只有编辑区能接）
- 只显示文件名、正文区空白
- 预览态下点击正文能出现光标或能输入
- 快速切换后显示的是上一个文件

**INVEST**：I ✅ 不依赖编辑模式｜N ✅ 未规定预览库与是否支持缩放｜V ✅ 学生第一入口｜E ✅ 拖放 + 既有预览组件｜S ✅ 1 天｜T ✅ 全是「是否出现／多少秒／显示哪个文件」

**实现**：`src/lib/openFile.ts`、`src/components/PreviewPane.vue`、`src/App.vue`　**场景**：A

### US-02 编辑并保存回原名文件

**用户故事**

```
角色：作为一名只想改一个错别字的学生
功能：我想要在预览页点「编辑」改完再存回本地
价值：以便不用为了一个错别字去换一个软件，也不用把文件上传给任何人
```

**对应需求**：FR-EDT-01、FR-EDT-02、FR-SAV-01、FR-SAV-02

**验收标准**

场景：修改内容并保存下载
```
Given 用户已打开 报告.docx 且处于预览态
When  用户点击「编辑」，待编辑器加载完成后修改正文第一行
And   用户点击「保存下载」
Then  浏览器应下载一个文件，文件名为 报告.docx
And   重新用本应用打开该文件时，第一行应为修改后的文字
```

场景：未做修改直接保存
```
Given 用户处于编辑态且未修改任何内容
When  用户点击「保存下载」
Then  下载文件名应沿用原名
And   状态栏应说明"未改动内容"，不得声称已保存修改
```

场景：光标位置正确
```
Given 用户已进入编辑态且正文可见
When  用户点击正文第 3 行的某一个字
Then  文本光标应落在该行文字之内
And   光标与文字的垂直偏移不应超过半行高
```

**不算通过**
- 光标固定显示在文字上方一整行
- 保存后文件打不开或修改丢失
- 文件名变成 `报告.docx.docx` 或 `报告(1).docx`
- 点「保存下载」无反应也没有任何提示

**INVEST**：I ✅ 与 US-04／US-06 可分别交付｜N ✅ 未规定保存通道实现｜V ✅ 「只读预览库不能改」正是竞品空位｜E ⚠️ 保存依赖编辑器导出按钮，含不确定性｜S ⚠️ 2 天已达上限｜T ✅ 可判真假

**实现**：`src/components/EditorHost.vue`、`src/lib/editorAdapter.ts`、`src/lib/saveFile.ts`　**场景**：B
**状态**：⚠️ 「保存下载」这条链路**尚未端到端实测**。对外只能表述为「编辑器内工具栏导出可用」。

### US-03 格式识别与明确拒绝

**用户故事**

```
角色：作为一名误把 txt 后缀改成 docx 的普通用户
功能：我想要在打开前被告知"这不是 docx"
价值：以便不会对着白屏以为是自己电脑坏了，也不用反复重试
```

**对应需求**：FR-FILE-03、FR-ERR-01

**验收标准**

场景：扩展名与内容不符
```
Given 用户把 笔记.txt 重命名为 笔记.docx
When  用户把该文件拖入工作台
Then  系统应拒绝打开并提示"文件扩展名是 .docx，但内容不是有效的 Office 文档（不是 ZIP 容器）"
And   侧栏不应新增记录
And   界面框架应保留，用户仍可继续打开其它文件
```

场景：任意异常不导致白屏
```
Given 用户已在工作台会话中打开了文件
When  渲染过程中发生一个未捕获异常
Then  界面应出现红色错误横幅并显示可读原因
And   横幅中应提供「复制」按钮把错误全文复制到剪贴板
And   关闭横幅后界面仍可继续操作
```

**不算通过**
- 白屏
- 把错误文件当成空文档打开
- 提示文案是"文件损坏"而不区分"你改错了后缀"
- 提示里出现 `[object Object]`、`undefined` 或英文堆栈

**INVEST**：I ✅ 完全独立｜N ✅ 不限文案与样式｜V ✅ 演示现场最易翻车的一条｜E ✅ 扩展名 + 文件头双重校验已有｜S ✅ 0.5 天｜T ✅ 可判真假

**实现**：`src/lib/detectFormat.ts`、`src/lib/errors.ts`、`src/main.ts`　**场景**：D

### US-04 只看 docx 就只下 docx 的预览包

**用户故事**

```
角色：作为一名在机房或弱网环境打开网页的学生
功能：我想要只看 docx 时不要顺带下载 Excel 与幻灯片的解析器
价值：以便不必为看一眼文档就等半分钟
```

**对应需求**：FR-PRV-02、NFR-PERF-03

**验收标准**

场景：只打开 docx 时按需加载
```
Given 用户在当前浏览器中首次打开工作台（无缓存）
When  用户只打开一个 docx
Then  Network 面板按 JS 过滤时不应出现 xlsx / pptx / pdf 的预览包
And   该次打开产生的传输总量不应超过 2 MB
```

场景：切换格式才加载对应包
```
Given 用户已打开一个 docx
When  用户再打开一个 xlsx
Then  此时才应出现 xlsx 的预览包
And   切回 docx 时其内容不应丢失或重新下载
```

**不算通过**
- 打开一个 docx 就下载约 24 MB 的全部预览包
- 切回来时内容错乱或空白
- 打开 md 时仍触发 `@vue-office` 相关下载

**INVEST**：I ✅ 与 US-01 目标不同可分别验收｜N ✅ 不限 `import()` 还是分包配置｜V ✅ 决定弱网能否用｜E ✅ `preview.ts` 已按需加载｜S ✅ 1 天｜T ✅ 面板里有没有出现某个包可判

**实现**：`src/lib/preview.ts`　**验证**：NFR-PERF-03（实测符合）

### US-05 文件零上传，断网可证

**用户故事**

```
角色：作为一名要处理成绩单这类含个人信息表格的行政人员
功能：我想要在断网状态下照样打开并预览文件
价值：以便能确认没有任何一个字节离开这台机器
```

**对应需求**：FR-FILE-04、NFR-PRIV-01

**验收标准**

场景：断网后仍可打开
```
Given 工作台已被完整加载过一次（走了缓存）
When  用户断开网络后拖入 docx 与 xlsx
Then  两种格式都应正常显示内容
And   不应出现红色错误横幅
```

场景：不存在上传请求
```
Given 用户完成一次完整的打开与预览
When  用户在 Network 面板按 method:POST 过滤
Then  请求数应为 0
And   域名列表只应出现本机地址（localhost / 127.0.0.1 / 局域网 IP），不得出现任何第三方域名
```

**不算通过**
- 出现任何到外部域名的请求（哪怕是统计脚本或 Web 字体）
- 断网后内容区空白且没有说明
- 只有"架构上没写上传代码"的说法，而没有 Network 证据

**INVEST**：I ✅ 纯验证型、无需新代码｜N ✅ 断网方式不限（拔网线／关 WiFi／Offline）｜V ✅ 本项目唯一的架构级卖点｜E ✅ 只需确认既有链路｜S ✅ 0.5 天｜T ✅ 请求数与域名可数

**实现**：架构保证（零后端）
**状态**：⚠️ **录屏证据尚未留档**，结论目前依据「架构上无上传通道」。答辩前必须补录屏 + Network 截图。

### US-06 编辑器加载有进度与超时说明

**用户故事**

```
角色：作为一名在局域网另一台设备上做课堂演示的教师
功能：我想要在等待编辑器加载时看到已经等了多少秒、超时后知道可能原因
价值：以便不会以为"这个网页坏了"而当场放弃演示
```

**对应需求**：FR-EDT-04

**验收标准**

场景：加载过程中可见进度
```
Given 用户首次点击「编辑」（需下载约 199 MB 的编辑内核）
When  遮罩出现并持续 5 秒
Then  遮罩应在点击后 100 毫秒内出现
And   遮罩应显示"已等待 N 秒"，且 N 每秒递增 1（误差不超过 1 秒）
And   遮罩应说明数据量与"之后会被浏览器缓存"
```

场景：超过阈值仍未完成
```
Given 加载遮罩已显示超过 60 秒
When  用户继续等待
Then  界面应出现"超过 60 秒仍未完成"的提示
And   提示应给出可操作的替代方案（如先用「预览」模式查看）
And   加载失败时应可按提示切回预览，且遮罩停止转圈
```

**不算通过**
- 遮罩只有转圈没有秒数
- 加载失败后仍在转圈
- 超时提示只说"加载失败"、不给后续动作
- 加载完成后遮罩残留或秒数继续增长

**INVEST**：I ✅ 遮罩独立于编辑器｜N ✅ 不限倒计时实现｜V ✅ 对应已发生缺陷「局域网首访被误判为编辑不了」｜E ✅ 已有加载态基础｜S ✅ 1 天｜T ✅ 秒数与提示可判

**实现**：`src/components/EditorHost.vue`、`src/components/StatusBar.vue`
**状态**：⚠️ **阈值口径冲突，须先统一**：需求 FR-EDT-04 写 180 秒，代码实现为 60 秒。
两者只能留一个，否则本条第二个场景无法判定。建议以代码 60 秒为准并回改需求。

### US-07 会话内多文件管理与切换

**用户故事**

```
角色：作为一名需要对比多份学生作业的教师
功能：我想要在同一会话里同时打开多份文档并在侧栏随时切换、单独关闭
价值：以便不必反复重新选文件，也能清楚知道当前正在看哪一份
```

**对应需求**：FR-FILE-01、FR-PRV-04、FR-UI-01

**验收标准**

场景：同时打开多份并切换
```
Given 用户已打开 docx、xlsx、pptx 三个文件
When  用户依次点击侧栏中的三条记录
Then  编辑区应显示被点击文件的内容
And   被点击的记录应高亮为当前文件
And   侧栏应显示每个文件的格式与体积
```

场景：关闭当前文件
```
Given 侧栏中有 3 条记录且当前选中的是第 2 条
When  用户点击第 2 条记录的关闭按钮
Then  该记录应从侧栏移除
And   当前文件应自动切换为相邻记录，编辑区不应空白
And   磁盘上的原始文件不受任何影响
```

**不算通过**
- 关闭后编辑区空白且没有提示
- 关闭按钮误触发文件打开
- 侧栏记录与实际显示内容不一致

**INVEST**：I ✅ 与打开／预览可分别验收｜N ✅ 不限侧栏样式｜V ✅ 对比作业的真实场景｜E ✅ `FileSidebar` + 会话状态已有｜S ✅ 1 天｜T ✅ 记录数与高亮可判

**实现**：`src/App.vue`、`src/components/FileSidebar.vue`

### US-08 md 笔记预览

**用户故事**

```
角色：作为一名经常收到同学发来的 md 笔记的学生
功能：我想要把 md 文件拖进网页就看到排好版的标题、列表和代码
价值：以便不用为了读一份笔记去装 Typora 或在编辑器里翻源码
```

**对应需求**：FR-MD-01~06

**验收标准**

场景：拖入 UTF-8 md 看到排版
```
Given 用户有一份包含标题、列表、代码块、表格、引用的 UTF-8 md 文件
When  用户把该文件拖入工作台
Then  1 秒内正文应显示排版结果：井号标题渲染为一级标题、短横线渲染为带项目符号的缩进行
And   围栏代码块应保留换行与缩进，并在右上角显示语言名
And   管道表格应渲染为带表头的表格
And   状态栏格式徽章应显示 md
```

场景：md 不进入编辑内核
```
Given 当前打开的文件为 md
When  用户查看顶栏的「编辑」按钮
Then  该按钮应为禁用态并提示"编辑内核只认 Office 格式"
And   强行触发时不应产生 sdkjs / x2t 的下载请求
```

场景：内容里的脚本不执行
```
Given md 文件中含有 <script>alert(1)</script> 与 <img src=x onerror=alert(1)>
When  用户打开该文件
Then  界面不应弹出任何对话框
And   上述内容应只作为普通文字显示
And   DOM 中不应存在 script 标签
```

**不算通过**
- md 显示为纯文本（`#` 原样露出）
- 脚本被执行（弹窗）
- 打开 md 时触发 199 MB 编辑内核下载
- 超过上限时标签页卡死而非提示截断

**INVEST**：I ✅ 只走预览链路｜N ✅ 不限解析库，只约束排版正确、不执行脚本、中文不乱码｜V ✅ 学生读笔记的高频场景｜E ✅ 解析器已有且带 19+ 条测试｜S ⚠️ 2 天已达上限，编辑部分已拆出｜T ✅ 可判真假

**实现**：`src/lib/md/*`、`src/components/MarkdownPreview.vue`、`detectFormat.ts`、`preview.ts`　**场景**：F
**备注**：源码当前落在工作副本 `liteoffice-vue/`，尚未同步到本仓库 `src/`。
