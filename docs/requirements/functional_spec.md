# 功能需求规范（Functional Specification）

> 文档编号：REQ-FS-001  
> 版本：1.0  状态：已评审  
> 关联：`problem_definition.md`、`nonfunctional_spec.md`  
> 追溯：每条需求标注「实现位置」与「验证方式」，见第 6 节追溯矩阵

---

## 1. 范围

本规范描述 LiteOffice（Vue 版）在浏览器内提供的外部可见功能行为。
覆盖：文件打开、预览、编辑、保存、界面状态、错误处理、配置开关。

不覆盖：部署运维、桌面端打包、协作与账号体系（见第 4 节「非目标」）。

## 2. 角色

| 角色 | 说明 |
|---|---|
| 用户 | 通过浏览器使用应用的人 |
| 开发者 | 通过 `features.ts` 与 `EditorAdapter` 接入或裁剪能力的人 |

## 3. 需求约定

| 字段 | 含义 |
|---|---|
| **编号** | `FR-<模块>-<序号>`，全仓库唯一，Issue 中可直接引用 |
| **优先级** | P0 必须 / P1 应该 / P2 可选 |
| 验收标准 | 必须可判断真假，禁止"体验良好"这类表述 |

---

## 4. 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 宏 / VBA 执行 | 安全与工程量双重不可行 |
| 多人协作、评论、版本历史 | 需要服务端，与"零后端"定位冲突 |
| 账号体系、云存储 | 同上；且会引入隐私风险 |
| 复杂排版高保真（论文式版式、目录联动） | 依赖成熟引擎的完整能力，超出课程周期 |
| 从零开发 Office 引擎 | 工程量以人年计，规划中已明确排除 |
| PDF 注释 / 表单填写 | 所用本地化包不具备该能力 |

## 5. 功能需求

### 5.1 FR-FILE 文件打开

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-FILE-01** | 用户可点击「打开文件」选择一个或多个文档 | P0 | 点击后弹出系统文件选择框；选择 3 个文件后侧栏出现 3 条记录 |
| **FR-FILE-02** | 用户可将文件拖放到窗口任意位置打开 | P0 | 拖入文件时出现虚线遮罩与「松手即可渲染」提示；松开后文件被打开 |
| **FR-FILE-03** | 系统按扩展名识别格式，非法格式给出明确拒绝 | P0 | 拖入 `.txt` 时状态栏提示「只支持 …，这个文件是 .txt」，且不进入渲染 |
| **FR-FILE-04** | 系统对可解压格式做 ZIP 头校验，防止扩展名伪造 | P1 | 把 `.txt` 改名成 `.docx` 后拖入，被判定为非法并提示，不产生白屏 |
| **FR-FILE-05** | 用户可在侧栏切换当前文档 | P0 | 点击侧栏记录，编辑区切换到该文档；切换过程无残留内容 |
| **FR-FILE-06** | 用户可关闭侧栏中的某个文档 | P1 | 点击记录右侧 ×，记录消失；关闭当前文档后编辑区回到空状态 |
| **FR-FILE-07** | 文件全程不离开本机 | P0 | 打开文档期间，浏览器 Network 面板无任何上传请求；断网后仍可完成打开与预览 |

### 5.2 FR-PREVIEW 预览模式

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-PREVIEW-01** | 打开文档后**默认进入预览模式**并渲染内容 | P0 | 拖入 docx 后 1 s 内显示文档内容，无需额外操作 |
| **FR-PREVIEW-02** | 预览支持 docx / xlsx / pptx / pdf | P0 | 四种格式各打开一次，均能显示内容 |
| **FR-PREVIEW-03** | 预览组件按格式**按需加载** | P1 | 只打开 docx 时，Network 中不出现 excel / pptx / pdf 的预览包 |
| **FR-PREVIEW-04** | 预览模式为只读，不响应文字编辑 | P0 | 预览状态下点击正文无光标、无法输入 |
| **FR-PREVIEW-05** | 不支持的格式给出可读提示而非空白 | P1 | 预览某未支持格式时显示「暂不支持预览 X 格式」 |
| **FR-PREVIEW-06** | 快速切换文档时不出现内容错配 | P1 | 连续快速切换 3 个文件，最终显示的始终是最后一个文档 |

### 5.3 FR-EDIT 编辑模式

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-EDIT-01** | 用户可在「预览 / 编辑」间切换 | P0 | 点击「编辑」进入编辑态；点击「预览」回到只读态，且不报错 |
| **FR-EDIT-02** | 编辑模式加载 ONLYOFFICE 编辑器并打开当前文档 | P0 | 编辑态显示完整菜单栏与文档页面；状态栏显示「第 1 页 共 N 页」 |
| **FR-EDIT-03** | 编辑模式支持 docx / xlsx / pptx | P0 | 三种格式均能进入编辑器并修改内容 |
| **FR-EDIT-04** | 编辑区光标位置与文字基线一致 | P0 | 点击正文后，光标落在文字所在行内，不出现整行偏移 |
| **FR-EDIT-05** | 加载期间显示进度，而非「点了没反应」 | P1 | 编辑态出现遮罩，显示「正在加载编辑器… 已等待 N 秒」；加载完成后遮罩消失 |
| **FR-EDIT-06** | 加载超时给出明确失败原因 | P1 | 180 s 未完成时提示「网络太慢 / 内存不足 / 浏览器不支持 WebAssembly」 |
| **FR-EDIT-07** | 切换文档时释放旧编辑器实例 | P1 | 在编辑态连续切换 3 个文档，无重复 iframe、无内存持续增长迹象 |

### 5.4 FR-SAVE 保存

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-SAVE-01** | 用户可点击「保存下载」取回编辑后的文件 | P0 | 修改内容后点击，浏览器下载出一个 `.docx`，打开可见修改 |
| **FR-SAVE-02** | 下载文件名沿用原文件名 | P1 | 原文件 `报告.docx`，下载得到 `报告.docx`（不变成 UUID 或 `download.bin`） |
| **FR-SAVE-03** | 预览模式下「保存」语义为「另存原文件」 | P1 | 预览态点保存，下载原文件，状态栏说明「预览模式不会修改内容」 |
| **FR-SAVE-04** | 保存过程中给出进行中提示 | P1 | 点击后状态栏显示「保存中」类提示，不出现界面假死无反馈 |
| **FR-SAVE-05** | 保存失败时说明原因与替代操作 | P1 | 找不到导出按钮时提示「请直接在编辑器工具栏点导出，然后再点这里的保存」 |

### 5.5 FR-UI 界面与状态

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-UI-01** | 三栏布局：侧栏 / 编辑区 / 可选助手面板 | P0 | 默认显示侧栏 + 编辑区；助手面板默认关闭 |
| **FR-UI-02** | 顶栏显示当前文件名与格式徽标 | P1 | 打开 `报告.docx` 后顶栏显示文件名与蓝色 DOCX 徽标 |
| **FR-UI-03** | 状态栏反映最近一次操作结果 | P1 | 打开成功显示「已打开」；失败显示红色错误文案 |
| **FR-UI-04** | 空状态给出引导 | P2 | 无文档时编辑区显示「打开一个文档」与操作提示，不显示空白 |
| **FR-UI-05** | 界面在窄窗口下不塌陷 | P2 | 窗口缩至 800 px 宽时，侧栏与编辑区仍可见，不出现重叠 |

### 5.6 FR-ERR 错误处理

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-ERR-01** | 任何未捕获异常都不导致整页白屏 | P0 | 人为触发编辑器装载失败，页面仍保留界面框架，并出现红色横幅 |
| **FR-ERR-02** | 错误横幅显示完整可读信息 | P1 | 横幅文字不被截断，可换行；提供「复制」按钮 |
| **FR-ERR-03** | 错误可关闭并继续操作 | P2 | 点击 × 后横幅消失，界面可继续使用 |

### 5.7 FR-CFG 配置与可扩展性

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| **FR-CFG-01** | 可通过配置关闭编辑器，退化为占位实现 | P1 | 设 `features.editorEnabled = false` 后，编辑区显示文件信息，不报错 |
| **FR-CFG-02** | 可通过配置显示/隐藏助手面板 | P2 | 设 `features.agentEnabled = true` 后出现右侧面板 |
| **FR-CFG-03** | 更换编辑器只需改一处 | P1 | 全仓库对 ONLYOFFICE 的引用仅出现在 `editorAdapter.ts` 与 `main-editor.ts` |

## 7. 端到端验收场景

### 场景 A：只读查看（应始终可用）

1. 打开应用 → 拖入 `报告.docx`
2. **期望**：1 s 内显示文档内容；顶栏出现文件名与 DOCX 徽标；状态栏提示已打开
3. 点击正文 → **期望**：无光标，不可输入（只读）

### 场景 B：编辑并保存（核心闭环）

1. 拖入 `报告.docx` → 点右上「编辑」
2. **期望**：出现加载遮罩并显示秒数；加载完成后显示编辑器与「第 1 页 共 N 页」
3. 点击正文 → **期望**：光标落在文字行内
4. 输入几个字 → 点顶部「保存下载」
5. **期望**：下载出 `报告.docx`；用 Office 或本应用重新打开，修改存在

### 场景 C：多文件切换

1. 依次拖入 docx、xlsx、pptx
2. 在侧栏来回切换
3. **期望**：内容正确切换；无旧内容残留；无报错横幅

### 场景 D：异常不白屏

1. 打开 `features.editorEnabled = true` 但临时改名 `public/onlyoffice` 使其缺失
2. 点「编辑」
3. **期望**：不白屏；出现红色横幅说明加载失败；可切换到「预览」继续使用

### 场景 E：局域网他人访问

1. 本机 `npm run dev`，另一台设备同 WiFi 访问 `http://<内网IP>:<端口>/`
2. **期望**：页面可打开；预览可用；编辑需等待 1–3 分钟（199 MB 首次加载）
