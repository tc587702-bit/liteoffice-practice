# 作业 3：沟通与风险管理计划

LiteOffice｜5 人小组｜周期 5 周｜2026-10-17

## 1. 制定沟通管理计划

| 沟通内容 | 沟通频度 | 沟通方式 | 产出物 |
|---|---|---|---|
| 目标用户、需求范围与非目标（分析） | 每天 | 面对面 + 协作平台 | 《问题定义》、需求规范 |
| 模块划分、接口边界、技术路线取舍（设计） | 定稿前密集 | 视频会议 + PR 讨论 | 架构图、决策记录 |
| 每日进度与阻塞（开发） | 每天 15 分钟 | 面对面 / 语音 | 站会记录，阻塞转 Issue |
| 代码评审与踩坑同步（开发） | 每次提交 / 即时 | 项目协作平台（PR）+ 即时通信 | 评审结论，写入代码注释 |
| 验收结果与缺陷复现（测试） | 每天 | 项目协作平台（Bug tracker） | 缺陷记录 |
| 演示流程与必须说明的限制（发布） | 发布前 1 次 | 视频会议 + 预演 | 演示脚本、README「已知问题」 |
| 后续需求与依赖评估（迭代） | 每周 1 次 | 项目协作平台（Issue） | 反馈分类与下轮计划 |

## 2. 制定风险管理计划

| 风险名称 | 所属维度（如资源、项目管理、外部因素、技术、进度） | 风险说明 | 影响程度（重要性） | 对工作量的影响（高、中、低） | 对进度和成本的影响（高、中、低） | 优先权（紧急程度） | 跟踪频率 |
|---|---|---|---|---|---|---|---|
| 编辑内核坐标系错乱 | 技术 | 挂入子区域后文字正常但光标偏上一行，无法输入 | 高 | 高 | 高 | P0 | 每天（已关闭） |
| 保存无法获取产物 | 技术 | 库无公开保存接口，只能触发导出并截获产物，链路脆弱 | 高 | 高 | 高 | P0 | 每天 |
| 新环境无法复现运行 | 项目管理 | npm 11 跳过 postinstall，入口文件缺失，报错却指向包本身 | 中 | 中 | 中 | P1 | 每周（已关闭） |
| 商业字体法务风险 | 外部因素 | 包内 16 个字体为等线、宋体、Arial 等微软商业字体 | 高 | 中 | 低 | P0（若公开） | 每周 |
| 体积过大致首访失败 | 外部因素 | 编辑需下载约 199 MB，局域网首访 1–3 分钟无反馈 | 中 | 中 | 中 | P1 | 每天 |
| 关键人员缺席 | 资源 | 集成负责人缺席则前两项无人接手 | 高 | 高 | 高 | P1 | 每周 |
| 工期不足与演示风险 | 进度 | 五周内需完成集成与演示，演示机首访需预热 | 高 | 高 | 高 | P0 | 每天 |

**应对**：技术用官方 demo 对照定位、保存保留人工兜底；先做原型再定方案；`npm run setup` 解决首运行；
字体三处披露、公开前替换；遮罩显示等待时长；每人指定备份人；进度按"保打开预览 → 保编辑保存 → 砍附加功能"裁剪。
站会 1 分钟过风险表，阻塞超 4 小时上报组长。
